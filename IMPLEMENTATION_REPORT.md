## Architecture discovered

- Two Gradle modules: `:app` (Compose UI + services) and `:metaphony` (native
  TagLib wrapper via NDK/CMake; TagLib is a git submodule). Translations are
  generated by **phrasey** (`npm run prebuild`) from `.phrasey/schema.toml` +
  `i18n/*.toml` into git-ignored `*.g.kt` and `app/src/main/assets/i18n/*.json`.
- `Symphony` is an `AndroidViewModel` that owns every service (`settings`,
  `database`, `groove`, `radio`, `translator`). It was created only by MainActivity
  via `viewModels()`.
- **Playback**: `Radio` (controller) → `RadioPlayer` (wraps `android.media.MediaPlayer`;
  fade via `RadioEffects.Fader`, gated by `forceFade || settings.fadePlayback`).
  `RadioSession` owns a **`MediaSessionCompat`** (the app uses `androidx.media:media`,
  **not** Media3). `RadioShorty` funnels play/pause. `RadioNotification(+Service)`
  is the foreground media service. Audio focus / headset handled by `RadioFocus` /
  `RadioNativeReceiver`.
- **Library**: in-memory repositories under `groove` (song/album/artist/genre/
  playlist) built by scanning; folder tree in `SongRepository.explorer`.
- **Playlists**: Room entity `Playlist` in `PersistentDatabase` (was v1), managed by
  `PlaylistRepository`.
- **Artwork**: Coil `ImageRequest`s built by `createHandyImageRequest`; cover files
  cached under `dataDir/covers`.
- **Now Playing**: `showLyrics` is a `MutableStateFlow` toggle; the large cover uses
  a `swipeable` modifier (already supporting all 4 directions) + tap-to-open-album.

## Feature implementations

### 1. Configurable pause/resume fade
- New `settings.fadeOnPauseResume` (`BooleanEntry`, default **true**).
- `PlaybackFade.shouldFade(mainFadeEnabled, fadeOnPauseResume, isUserPauseResume)` is
  the single decision used by `Radio.start()` and `Radio.pause()`:
  - fresh track start → fades when the master option is on (unchanged behaviour);
  - user pause/resume → fades only when **both** options are on.
- `start()` sets full volume instantly when not fading (never resumes silent).
- The sleep timer keeps `pause(forceFade = true)` (forced fade preserved).
- UI: a dependent `SettingsSwitchTile` nested under "Fade playback"
  (`PlayerSettingsView`), disabled + greyed when the master is off, value preserved.
  `SettingsSwitchTile` gained an `enabled` flag.

### 2. Swipe down on Now Playing cover → lyrics
- Wired the existing `swipeable` modifier's `onSwipeDown` on the large artwork only
  (`BodyCover`) to the same open-lyrics behaviour as the lyrics button (in-place
  `showLyrics` toggle for the ReplaceArtwork layout, navigation to `LyricsViewRoute`
  for SeparatePage). Gesture decision extracted to `resolveSwipeDirection` (tested).
  Mini-player unaffected; cover tap and lyrics button preserved.

### 3. Custom playlist covers
- `Playlist.customCoverPath: String?` column; **Room migration 1 → 2**
  (`ALTER TABLE playlists ADD COLUMN customCoverPath TEXT`). Existing rows → null.
- `PlaylistCovers` util: content-resolver read → sampled decode → EXIF orientation →
  centre-crop square → scale ≤ 1024 → WebP saved atomically to
  `files/playlist_covers/<id>_<timestamp>.webp`. Timestamped names invalidate the
  Coil cache on replace.
- `PlaylistRepository`: `setCustomCover` / `removeCustomCover`; cover preserved
  through update/rename/local re-parse; deleted with the playlist; orphan cleanup on
  fetch. Precedence: valid custom cover → generated artwork → placeholder; missing
  file falls through.
- UI: "Change cover" / "Remove custom cover" in `PlaylistDropdownMenu` (shared by the
  grid tile and the detail screen), using the **Android Photo Picker** (SAF fallback)
  with a square preview + confirm dialog.

### 4. Android Auto
- `RadioBrowserService : MediaBrowserServiceCompat` sharing the existing
  `MediaSessionCompat` token and playback engine.
- `SymphonyProvider` makes `Symphony` process-scoped so the service works when
  Android Auto starts the app cold (no activity). MainActivity now obtains the shared
  instance.
- `RadioBrowser` builds the browse tree (root → Songs/Albums/Artists/Playlists/
  Genres/Folders → items) from the in-memory repositories and resolves play/search.
- `MediaId` — base64url, separator-safe ids encoding the play context, so selecting a
  song builds the correct album/artist/playlist/genre/folder queue.
- Session callbacks `onPlayFromMediaId` / `onPrepareFromMediaId` / `onPlayFromSearch`
  route through `Radio` (audio focus + fade preference respected).
- `ArtworkProvider` — read-only, non-exported content provider; the browser service
  grants per-uri read to the connecting client so covers/artwork render in the car.
- Manifest: exported browser service with the `MediaBrowserService` intent filter,
  `res/xml/automotive_app_desc.xml` (`uses media`), and the car application meta-data.
- No lyrics on the driving screen.

## Security note: inherited upstream secrets

The upstream fork point (`dd04b87`) tracks `secrets/signing_key.jks` — an
**unencrypted PKCS#12 keystore** — together with `secrets/secrets.txt` containing
its **plaintext passwords**, despite `.gitignore` already listing `secrets`. These
belong to the upstream Symphony project.

MAZIKA does not use them: release signing reads a keystore supplied through
environment variables (`SIGNING.md`), and the release build falls back to an
unsigned APK when none is present. They have been **removed from the `mazika-main`
branch** (commit `chore: remove inherited upstream signing secrets`) so this fork
does not redistribute another project's private signing key.

They do still exist inside the inherited upstream commit object; purging them from
there would require rewriting the upstream history this fork is based on, which
would break the recorded fork point. No secrets were introduced by this work, and
no keystore or password is committed on the MAZIKA branch.

## Remaining limitations
- **Android Auto / car**: not verified on a physical car, the Desktop Head Unit or
  Media Controller Test in this environment (headless build machine, no phone/car
  attached). The implementation is compiled and the merged manifest is verified;
  device verification is required per `TESTING.md`.
- **Release signing**: no production keystore was provided; see the Release APK
  section and `SIGNING.md`.
- **Backup/restore of covers**: custom covers are app-private files and are **not**
  embedded in `.m3u` playlist exports (that format has no place for binary images).
  They are covered by Android's full-app auto-backup (allowBackup=true) but not by
  `.m3u` export/import.
- **Instrumented UI tests** (gesture, picker, migration on-device) were not run — no
  emulator/device attached; the pure decision logic is unit-tested instead.
